# راهنمای کاربر — Agent Factory (قدم‌به‌قدم)

این راهنما برای کسی است که می‌خواهد این سرویس را روی سیستم خودش (یا یک سرور) راه بیندازد، به مدل وصلش کند و ایجنت بسازد.
زبان رابط فارسی است و به English و Türkçe هم عوض می‌شود.

> **صادقانه:** مراحل «اجرای محلی» و بخش‌های داخل برنامه (ساخت ایجنت، workflow، کلید API) با تست و مرورگر امتحان شده‌اند.
> مراحل **Ollama** و **مدل واقعی با کلید واقعی** هنوز امتحان نشده‌اند؛ جای هرکدام علامت ⚠️ گذاشته‌ام. اگر جایی گیر کردید، بخش «رفع اشکال» آخر را ببینید.

---

## ۱. سه چیزی که لازم دارید

| چیز | چرا | گزینه‌ها |
|---|---|---|
| **۱. جایی که برنامه اجرا شود** | خود سرویس | سیستم خودتان (Docker یا پایتون)، یا یک سرور |
| **۲. دسترسی به یک مدل هوش مصنوعی** | ایجنت‌ها با مدل فکر می‌کنند | حساب Claude خودتان، کلید API، یا مدل محلی (Ollama) |
| **۳. حساب در برنامه** | ورود و جدا بودن داده‌ها | بار اول خودکار ساخته می‌شود |

هیچ چیز پولی تا وقتی دکمه‌ای را نزنید که بگوید «مدل را صدا می‌زند» اتفاق نمی‌افتد، و هر ساخت سقف بودجه‌ی خودش را دارد.

---

## ۲. نصب و اجرا

### روش الف) با Docker (پیشنهادی — یک دستور، بدون هیچ تنظیمی)

نیاز: Docker Desktop (ویندوز/مک) یا Docker Engine (لینوکس).

```bash
git clone https://github.com/todos125m/agent-factory.git
cd agent-factory
docker compose up --build
```

یا به‌جای آن `./start.sh` (ویندوز: `.\start.ps1`) که صبر هم می‌کند تا آماده شود و مرورگر را باز می‌کند.
وقتی آماده شد: **http://localhost:8000/app**

**چیزی لازم نیست پر کنید.** پایگاه داده (PostgreSQL) خودش بالا می‌آید، و رمز اصلی نگه‌داری کلیدها بار اول **خودکار ساخته می‌شود** و در volume به اسم
`af_data` می‌ماند (اگر خودتان در `.env` بگذارید، آن اولویت دارد). اولین ساخت چند دقیقه طول می‌کشد (دانلود پایتون و ابزار Claude).

نکته‌ها:
- **دسترسی:** فقط از همین سیستم باز می‌شود. برای موبایل/شبکه در `.env` بنویسید `AGENT_FACTORY_BIND=0.0.0.0` (و قبل از اینترنت، HTTPS بگذارید).
- **داده‌ها:** در volumeهای `postgres_data` و `af_data` می‌مانند؛ `docker compose down` آن‌ها را نگه می‌دارد ولی `down -v` پاک می‌کند. **از هر دو پشتیبان بگیرید**
  (`af_data` رمز اصلی است؛ بدون آن کلیدهای ذخیره‌شده خوانا نیستند).
- **به‌روزرسانی:** `git pull` و دوباره `docker compose up -d --build`.
- **مدل:** بخش ۴. برای حساب Claude یک خط در `.env` کافی است: `CLAUDE_CODE_OAUTH_TOKEN=...`.
- **Docker Hub خطای 403 می‌دهد** (در ایران معمول است): در `.env` بنویسید
  `PYTHON_IMAGE=mirror.gcr.io/library/python:3.11-slim` و `POSTGRES_IMAGE=mirror.gcr.io/library/postgres:16` (امتحان شده و جواب می‌دهد).
- **هنگام ساخت `CERTIFICATE_VERIFY_FAILED` می‌دهد** (آنتی‌ویروس مثل AVG/Avast «Web Shield» روی HTTPS نظارت می‌کند): گواهی ریشه‌ی آن را در پوشه‌ی
  `docker/ca/` بگذارید (راهنمایش در `docker/ca/README.md`، با دستور آماده‌ی PowerShell) یا هنگام ساخت اسکن HTTPS را خاموش کنید.

این مسیر روی سیستم همین پروژه (ویندوز + Docker 29) از صفر امتحان شد: ساخت image، بالا آمدن، ساخت حساب و کلید، و ماندن همه‌چیز پس از `down` و `up`.

### روش ب) بدون Docker (سبک‌ترین، با SQLite)

نیاز: پایتون ۳٫۱۱ یا بالاتر.

```bash
git clone https://github.com/todos125m/agent-factory.git
cd agent-factory
python -m venv .venv
.venv\Scripts\Activate.ps1          # لینوکس/مک:  source .venv/bin/activate
pip install -e .
uvicorn app.main:app                # سپس:  http://localhost:8000/app
```

**نکته‌ی مهم:** در این روش برنامه فایل `.env` را **نمی‌خواند**؛ متغیرها را در همان پنجره پیش از `uvicorn` ست کنید:
PowerShell: `$env:AGENT_FACTORY_SECRET_KEY = "رمز-شما"` — لینوکس/مک: `export AGENT_FACTORY_SECRET_KEY=رمز-شما`.

## ۳. اولین ورود

1. آدرس `/app` را باز کنید. **زبان** را انتخاب کنید (فارسی / English / Türkçe).
2. اولین نفری که وارد می‌شود، **حساب مدیر سرور** را می‌گیرد؛ ثبت‌نام جدا ندارد.
3. در «تنظیمات ← ترجیح‌های من» می‌توانید سطح توضیح (ساده تا فنی)، نمایش کد و ظاهر را عوض کنید.

## ۴. وصل کردن مدل (مهم‌ترین قدم)

در **تنظیمات ← «روش دسترسی به مدل»** یکی از سه روش را انتخاب می‌کنید.

| روش (نام در برنامه) | چه لازم دارد | هزینه | کیفیت | جست‌وجوی وب |
|---|---|---|---|---|
| **حساب Claude خودم** (`claude_account`) | اشتراک Claude + ابزار Claude Code | از اشتراک خودتان | بالا | بله |
| **کلید API** (`api_key`) | کلید API از Anthropic | پرداخت به ازای مصرف | بالا | بله |
| **Ollama (محلی)** (`ollama`) | نصب Ollama و دانلود یک مدل | رایگان | بسته به مدل و کارت گرافیک | **نه** |

### الف) حساب Claude خودم
- **بدون Docker:** یک بار در ترمینال `claude` را بزنید و وارد حساب شوید. همین کافی است.
- **با Docker/سرور:** روی سیستم خودتان `claude setup-token` را بزنید. توکن بلندی چاپ می‌کند؛ آن را در `.env` بگذارید:
  `CLAUDE_CODE_OAUTH_TOKEN=...` و دوباره `docker compose up -d`.

### ب) کلید API
دو راه:
1. **در `.env`** (برای همه‌ی حساب‌های این سرور): `ANTHROPIC_API_KEY=...`
2. **یا در خود برنامه، برای حساب خودتان** — «تنظیمات ← اتصال‌ها»: نام و کلید را وارد می‌کنید، کلید رمزگذاری می‌شود و دیگر نشان داده نمی‌شود
   (فقط `••••` و چهار نویسه‌ی آخر). با «آزمون اتصال» (فقط وقتی می‌زنید) می‌بینید ارائه‌دهنده کلید را پذیرفته یا نه. بعد در همان صفحه برای هر
   «نقش مدل» (مدیر، پژوهش، کدنویسی، ارزان) «کلید شما برای این نقش» را انتخاب می‌کنید. این راه به `AGENT_FACTORY_SECRET_KEY` نیاز دارد.

### ج) مدل محلی با Ollama (رایگان)
⚠️ این روش روی سیستم شما هنوز آزمایش نشده؛ محدودیت‌ها را بخوانید.

1. Ollama را نصب کنید (https://ollama.com) و یک مدل بکشید، مثلاً: `ollama pull qwen2.5:7b`
   (حدود ۴٫۵ گیگ؛ روی کارت‌های ۸ گیگ جا می‌شود).
   **ساده‌ترین راه با Docker:** Ollama را روی خود سیستم نصب کنید (کارت گرافیک مستقیم استفاده می‌شود) و در `.env` بنویسید
   `OLLAMA_BASE_URL=http://host.docker.internal:11434`. یا داخل Docker: `docker compose --profile ollama up`، بعد
   `docker compose exec ollama ollama pull qwen2.5:7b` و `OLLAMA_BASE_URL=http://ollama:11434` (GPU در ویندوز تنظیم اضافه می‌خواهد).
2. در «تنظیمات ← روش دسترسی به مدل» **Ollama (محلی)** را انتخاب کنید.
3. در همان صفحه، برای هر نقش مدل، **نام مدل** را بنویسید (مثلاً `qwen2.5:7b`)؛ پیش‌فرض برنامه `llama3.2` است.
4. **محدودیت‌ها:**
   - برنامه از مدل خروجی ساختاریافته (JSON) می‌خواهد؛ مدل‌های خیلی کوچک (۳ میلیارد و کمتر) اغلب خراب می‌دهند و قدم رد می‌شود.
   - ایجنت‌هایی که ابزار جست‌وجوی وب دارند (مثل «researcher» داخلی) روی Ollama کار نمی‌کنند.
   - کندتر است؛ هر فراخوانی حداکثر ۱۲۰ ثانیه وقت دارد. ارزیابی ایجنت (چند فراخوانی پشت هم) ممکن است چند دقیقه شود.
   - متن فارسی در مدل‌های کوچک ضعیف‌تر است.

### بودجه
هر پروژه و هر ساخت سقف دلار دارد (تنظیمات ← «بودجه و محدودیت‌ها»). قبل از هر فراخوانی پولی، بدترین حالت هزینه رزرو می‌شود و اگر از سقف بگذرد فراخوانی انجام نمی‌شود.

## ۵. اضافه کردن آدم‌ها و دستگاه‌ها

رمز عبور نداریم؛ ورود با **کد یک‌بارمصرف** است.

- **دستگاه دیگر خودتان** (مثلاً موبایل): در دستگاه وارد‌شده «تنظیمات ← ورود در دستگاه دیگر» را بزنید، کد ۱۰ دقیقه‌ای می‌دهد؛ در دستگاه دوم «ورود» و وارد کردن کد.
- **یک نفر دیگر:** فقط **مدیر سرور** می‌تواند حساب بسازد: «تنظیمات ← افزودن حساب (ایمیل)» ← «ساخت حساب و کد ورود». کد را به او بدهید تا وارد شود. هر حساب فقط پروژه‌ها و ایجنت‌ها و کلیدهای خودش را می‌بیند.

---

## ۶. اولین ایجنت شما

1. **ایجنت‌ها ← + ساخت Agent جدید.**
2. **فهم مسئله:** سیستم چند سؤال کوتاه می‌پرسد. «نمی‌دانم؛ پیشنهاد بده» هم می‌توانید بزنید.
3. **تأیید برداشت:** خلاصه را می‌خوانید و تأیید می‌کنید.
4. **طراحی:** یک بوم با ۸ شاخه می‌بینید. هر شاخه را بخوانید، اگر لازم است ویرایش کنید و «تأیید» بزنید. همه‌ی مجوزها پیش‌فرض خاموش‌اند. بعد طرح را تأیید کنید.
5. **ساخت:** رایگان و فوری.
6. **ارزیابی:** (پولی؛ فقط با دکمه‌ی شما) هر مورد آزمون عادی/مرزی/شکست اجرا و داوری می‌شود. اگر رد شد، به طراحی برمی‌گردید (حداکثر ۳ دور).
7. **فعال‌سازی:** فقط بعد از قبولی، با تأیید شما. بعد از آن ایجنت در پروژه‌ها قابل استفاده است و نسخه‌ها قابل برگرداندن‌اند.

---

## ۷. کار با پروژه

**پروژه‌ها ← + پروژه‌ی جدید** (هدف را بنویسید) ← «برنامه بریز»: مدیر وظیفه‌ها را به ایجنت‌ها می‌سپارد ← شما برنامه را تأیید می‌کنید ← در نقطه‌های تصمیم (صندوق تصمیم‌ها) جواب می‌دهید.
هرچه منتظر شماست در **صندوق تصمیم‌ها** جمع می‌شود. «توقف» پروژه همه‌چیز را فوراً نگه می‌دارد.

**workflow:** در «workflowها» چند ایجنت را به هم وصل می‌کنید (نتیجه‌ی یکی ← ورودی بعدی). ناسازگاری‌ها پیش از تأیید با دلیل نشان داده می‌شود؛ «ذخیره» چیزی را اجرا نمی‌کند؛ «اجرا در یک پروژه» وظیفه‌ها را می‌سازد و برنامه همچنان منتظر تأیید شماست.

---

## ۸. دادن ایجنت به یک برنامه‌ی دیگر (API)

«تنظیمات ← کلیدهای API (برنامه‌ای که ایجنت شما را اجرا کند)» ← نام، نسخه‌ی ایجنتِ فعال‌شده‌ی خودتان، پروژه، مجوزها و سقف‌ها ← «ساختن کلید».
کلید **فقط یک بار** نشان داده می‌شود؛ همان لحظه کپی کنید. برنامه‌ی بیرونی با آن می‌تواند اجرا شروع کند، وضعیت را بخواند و به پرسش‌های ایجنت جواب دهد؛
هیچ تأییدی را نمی‌تواند بدهد (ابزارها و تصمیم‌ها هنوز در صندوق منتظر شمایند). مثال در README بخش «External API».

---

## ۹. اگر برای چند نفر یا روی اینترنت می‌گذارید

- حتماً **HTTPS** و یک **reverse proxy** (nginx، Caddy…) جلوی برنامه بگذارید و در `.env` بنویسید `AGENT_FACTORY_BEHIND_PROXY=1`.
- از **PostgreSQL** استفاده کنید (Docker خودش دارد) و از volume و `AGENT_FACTORY_SECRET_KEY` پشتیبان بگیرید.
- حساب‌ها را فقط مدیر می‌سازد؛ کلید مدل هر نفر را می‌تواند جدا در «اتصال‌ها» بگذارد.
- تلاش‌های ناموفق کلید API تا ۲۰ بار در دقیقه از یک نشانی مجاز است؛ محدودیت نرخ در proxy هم بگذارید.
